# Cowrie

Analysis scripts for the Cowrie SSH/Telnet honeypot (credential harvesting, session logging, payload capture).
Findings: [reports/cowrie-findings.md](reports/cowrie-findings.md) · Sample data: [sample_logs/](sample_logs/)

## Log path

All scripts use:

```
LOG_DIR = '/home/cowrie/cowrie/var/log/cowrie'
```

If your installation uses a different path, edit this constant at the top of each script.

## Scripts

| Script | Purpose |
|--------|---------|
| `analyze_cowrie.py` | 10-day overview: sessions, unique IPs, top IPs, passwords, commands |
| `attack_stats.py` | Full statistics report with ASCII bar charts, HASSH fingerprints, session durations |
| `classify_cowrie.py` | Session classifier (HASSH + regex + ML) |
| `session_analysis.py` | Session depth, command sequences, attacker profiles |
| `attacker_profiling.py` | Attacker profiling based on session data |
| `timeline_builder.py` | Forensic timeline of a single session |
| `generate_time_activity.py` | Activity over time |
| `analyze_creds_commands.py` | Credentials and commands analysis; writes `malware_commands.json` |
| `extract_downloads.py` | Downloaded files; writes `malware_files.json` |
| `analyze_uploads.py` | Uploaded files; writes `malware_uploads.json` |
| `analyze_payloads.py` | Static analysis of captured payloads |
| `analyze_chains.py` | Attack chains built from the three JSON files above |
| `log_loader.py` | Shared log-loading module (not run directly) |
| `install_dynamic_fs.sh` | Corporate honeyfs setup (replaces the default Cowrie filesystem) |

## Script dependencies

Most scripts are standalone. Two exceptions:

- [`log_loader.py`](log_loader.py) is a shared module used by [`session_analysis.py`](session_analysis.py), [`attacker_profiling.py`](attacker_profiling.py) and [`classify_cowrie.py`](classify_cowrie.py). Keep it in the same directory.
- [`analyze_chains.py`](analyze_chains.py) needs three input files generated by other scripts first:
  - `malware_commands.json` ← [`analyze_creds_commands.py`](analyze_creds_commands.py)
  - `malware_files.json` ← [`extract_downloads.py`](extract_downloads.py)
  - `malware_uploads.json` ← [`analyze_uploads.py`](analyze_uploads.py)

[`analyze_payloads.py`](analyze_payloads.py) also uses the system tools `file`, `strings`, `readelf` and `upx`:

```
apt install binutils upx-ucl
```

Python dependencies: `pip install -r ../requirements.txt`

## Corporate honeyfs

The default Cowrie filesystem looks like a generic Debian install, and experienced attackers recognise it immediately. [`install_dynamic_fs.sh`](install_dynamic_fs.sh) replaces it with a simulated corporate cluster:

- Kubernetes, Docker, Ansible, Terraform, Jenkins, GitLab Runner
- PostgreSQL, MySQL, Redis, RabbitMQ, Kafka, Zookeeper
- Prometheus, Grafana, Elasticsearch, Logstash, Kibana
- HashiCorp Vault, Consul, Nomad, Harbor registry, MinIO
- Fake credentials, SSH keys, database dumps and CI/CD artefacts

Every run generates randomised usernames, passwords, GitHub tokens and attacker IPs, so the environment looks different to each session.
